Use ← / → arrow keys or click the buttons in the bottom-right to navigate

The Challenge

  • Multiple product streams need reliable end-to-end test automation
  • Each team starts from scratch — inconsistent patterns & duplicated setup effort
  • Selectors break silently during UI refactors; failures are slow to diagnose
  • Test cases live in Test Management (Testmo/TestRail) disconnected from code
  • No shared CI/CD or environment safety standard across dev, stage, and prod

What We Built

One enterprise boilerplate that teams fork or clone. Every stream inherits the same Page Object toolkit, 3-tier safety locks, reporting, and Gemini 4 Argon skills out of the box — while staying free to add their own pages and specs.

Tech Stack

🎭 Playwright + TypeScript

Multi-browser, parallel, strictly typed. Page Object Model with a shared BasePage that wraps every action as a report step.

📊 HTML / Allure + TMS

Rich reports with screenshots, video, and traces on failure. Test cases link 1:1 via tmsCase(id) and sync automatically in CI.

🧠 Gemini 4 Argon

Interactive test generation, failure root-cause analysis, two-layer locator healing, and visual diff explanation without runtime CI flakiness.

🚀 Sharded GitHub Actions

Configurable parallel shards (1–8). Smoke tests on PRs, scheduled regressions, and manual workflow dispatch overrides.

🔐 Vault-Ready Credentials

Reads from .env locally and GitHub Secrets in CI. Swap to HashiCorp Vault by changing CREDENTIAL_PROVIDER=vault.

🛠️ Antigravity Skills

Four slash workflows: /project-setup, /local-setup, /create-tests, and /heal-locators.

/create-tests

From ticket & PR diff to committed spec file — guided by Gemini 4 Argon

  • 1
    Reads the ticket & dev PR diff
    Extracts title, description, comments, and developer code changes to catch undocumented UI updates.
  • 2
    Explores the live app via Playwright MCP
    Opens the route in Chromium, inspects the accessibility tree, and identifies stable data-hook / data-test attributes.
  • 3
    Proposes test steps for confirmation
    Happy path • negative • edge cases • accessibility (1 TMS step = 1 Playwright test).
  • 4
    Resolves TMS folder & creates cases
    Uses TMS_FOLDER_ID and TmsApiClient to register cases with automated + ai-generated tags.
  • 5
    Writes Page Object & Spec
    Generates strictly typed code, runs npm run lint && npm run type-check, and verifies the test passes on dev.

/heal-locators

Two-layer interactive selector repair via Playwright MCP

  • 1
    Auto-detects broken selector
    Reads test-results/ to locate the failing Page Object method, line number, and target URL.
  • 2
    Navigates the live page
    Playwright MCP opens the route and captures the current DOM state.
  • 3
    Ranks up to 3 candidates
    Ordered by stability: data-hook/testid → ARIA role → label/text → CSS.
  • 4
    Interactive patching & verification
    Shows the diff, applies the confirmed patch to src/pages/, and re-runs the spec.

Two-Layer Healing

Layer 1 — Runtime (SmartLocatorDiagnostics): Logs candidate replacements to console during a failure — zero file changes in CI.

Layer 2 — Interactive (/heal-locators): Confirm and patch the Page Object permanently.

Enterprise Toolkit & AI Capabilities

🔍 Virtualized DOM Table Reader

readAllVirtualizedRows() scrolls bidirectional virtualized lists keyed by data-index so unmounted top rows are preserved, verifying total count against "Showing N entries".

🔑 In-Memory Token Borrowing

InMemoryTokenClient intercepts the SPA's next outgoing network request to borrow its Bearer token for direct GraphQL and REST backend assertions.

♻️ On-Demand Data Supply & Teardown

EntitySupplyManager finds or provisions required records on dev and runs LIFO auto-cleanup in afterEach while protecting golden baseline IDs.

📦 Deep File Download Inspector

FileDownloadInspector parses downloaded streams to verify CSV headers/rows, PDF signatures (%PDF-), and ZIP/XLSX magic bytes.
