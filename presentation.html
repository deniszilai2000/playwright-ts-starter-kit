Common Pitfalls in Legacy & Runtime-AI Suites
  • Raw page.locator() calls scattered across hundreds of test files, creating high maintenance overhead when UI changes.
  • Runtime AI wrappers adding 4–8 seconds of network latency per click and masking real application regressions.
  • Mutating E2E tests accidentally altering shared staging or production records.
  • Plaintext credentials exposed in HTML reports and CI step logs.
The ArgonQA Engineering Standard
  • Strict Page Object Encapsulation enforced at compile time via custom ESLint AST rules.
  • 0–100 Selector Stability Scoring prioritizing W3C ARIA roles and explicit test attributes.
  • Self-Cleaning Test Data (EntitySupplyManager) with automatic LIFO teardown queues.
  • Redacted Secret Injection (fillSecure) paired with HashiCorp Vault, Doppler, or CI secrets.
Section 02 — System Design

Clean Four-Layer Separation of Concerns

Product and QA engineers only maintain readable Page Objects and Spec files. The underlying base engine, credential providers, and IDE workflows are standardized across the repository.

Layer 1 — Business-Readable Spec Layer (tests/e2e/)

Zero raw selectors permitted in specs. 1 TestOps step = 1 Playwright test with tmsCase() traceability and isDevRun() mutation guards.

Layer 2 — Typed Page Object & SLA Engine (src/pages/)

Extends BasePage: structured step logging, fillSecure() credential redaction, interceptApiCall() network assertions, and assertInteractionSla() timing checks.

Layer 3 — Resilience & Secret Brokers (src/helpers/)

Includes CredentialProvider (Env/Vault/Doppler), EntitySupplyManager (LIFO cleanup), FileDownloadInspector (PDF/XLSX verification), and SmartLocatorDiagnostics.

Layer 4 — Assisted Engineering Workflows (.agent/skills/)

Standardized IDE workflows (project-setup, local-setup, create-tests, heal-locators) backed by live Playwright DOM inspection.

// tests/e2e/smoke/navigation.spec.ts — Selector-Free Spec
import { test } from '../../../src/fixtures/base.fixture';
import { isDevRun } from '../../../src/helpers/environment.helper';

test.describe('Application Shell & Checkout (@smoke @sanity)', () => {
  test('1 — shell loads, authenticates, and sorts catalog @prod-safe', async ({
    navigationPage,
  }) => {
    await tmsCase(100001);

  test('2 — state-mutating checkout runs on verified dev only', async ({
    navigationPage,
  }) => {
    test.skip(!isDevRun(), 'Mutating test: runs on dev environment only');

});
Section 03 — Environment Governance

Three-Tier Environment Isolation

DEV Environment: Full CRUD + Automatic LIFO Teardown

On ENV=dev, regression suites provision test records on demand via EntitySupplyManager.findOrProvision() and automatically clean them up in reverse (LIFO) order after the test finishes—while protecting baseline records listed in PROTECTED_ENTITY_IDS.

$ ENV=dev npx playwright test --project=chromium

const order = await entitySupply.findOrProvision({
  entityType: 'SubscriptionOrder',
  findExistingFn: () => api.findDraftOrder(),
  provisionNewFn: () => api.createDraftOrder(),
  cleanupFn: (id) => api.deleteDraftOrder(id), // LIFO auto-cleanup
});
Section 04 — Authoring & Maintenance

Structured Test Authoring & Selector Stability Scoring

Engineers use repeatable workflows to turn product requirements into typed specs (create-tests) and repair broken selectors (heal-locators) using a transparent 0–100 stability scoring hierarchy.

create-tests — From Requirement to Verified Spec

1. Requirement & Diff Review: Analyzes ticket acceptance criteria and frontend PR diffs to identify affected routes and edge cases.

2. Live DOM Inspection: Opens the target application route in Chromium and maps accessible roles, labels, and test attributes.

3. Step-by-Step Test Plan: Proposes happy-path, validation, and @prod-safe test steps for engineer review before generating code.

4. Page Object & Spec Generation: Writes the typed Page Object and Spec file, links TestRail/Xray IDs, and verifies with npm run lint and npx playwright test.

Section 05 — Production Utilities

Built-In Helpers for Complex Web Applications

Pre-built utilities for common enterprise testing challenges: external secret managers, virtualized data tables, binary file exports, and API/SLA assertions.

1. Multi-Cloud Secret Broker (CredentialProvider)

Resolves credentials from .env, HashiCorp Vault, or Doppler—paired with fillSecure() so sensitive inputs are always logged as ***REDACTED*** in test reports.

const creds = await CredentialProvider.getCredentials(tenant, env);
await this.fillSecure(this.passwordInput, creds.password, 'SSO Password');
2. Virtualized Data Grid Reader (readAllVirtualizedRows)

Scrolls AG Grid, TanStack Virtual, or MUI DataGrid tables incrementally, indexing rows by data-index so recycled DOM rows are captured without duplicates.

const rows = await this.readAllVirtualizedRows({
  scrollContainer: this.gridViewport,
  rowLocator: this.gridRow,
  totalCountLocator: this.paginationSummary,
});
3. File Export Verifier (FileDownloadInspector)

Validates exported reports in memory by checking binary file signatures (%PDF- header, PK\x03\x04 XLSX zip container) and parsed CSV row counts.

const pdfMeta = await FileDownloadInspector.verifyPdfSignature(download);
expect(pdfMeta.byteLength).toBeGreaterThan(1024);
4. Atomic API Interception & SLA Checks (BasePage)

Combines UI triggers with backend HTTP response verification and client-side interaction timing budgets in a single method call.

await this.interceptApiCall('/api/v1/checkout', 200, async () => {
  await this.clickElement(this.confirmOrderBtn, 'Confirm Order');
});
